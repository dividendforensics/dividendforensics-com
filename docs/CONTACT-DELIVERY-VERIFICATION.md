# Research Desk delivery verification

## Evidence boundaries

Local field validation, a successful HTTP response from FormSubmit and a submission-success screen are not evidence of inbox receipt. Keep the public delivery limitation unless an authorized end-to-end check establishes receipt. Do not log credentials, mailbox contents unrelated to the test, or private message bodies in this public repository.

## Authorized one-message procedure

1. Record authorization separately before making an external submission. Use a unique non-sensitive test reference and the inquiry type **Question or correction**; project terms are not required.
2. Record UTC submission time, page URL, browser/device and test reference. Submit once, then wait for the result; do not resend to diagnose an uncertain response.
3. Record client result and service HTTP status separately from delivery. If the form service requests recipient activation, the authorized mailbox owner must handle it; do not claim success in the interim.
4. Check the intended recipient inbox and spam folder through authorized mailbox access. Match the unique test reference, recipient and received timestamp. If access is unavailable, mark receipt **unverified**, not failed or passed.
5. Retain private evidence in an approved private location. A public log should contain only a redacted result, timestamp, reference and verification scope.
6. Change public wording only after verified receipt. Describe a dated test, not a guarantee that every future message will arrive. Keep the email alternative and failure recovery intact.

## Separate local regression checks (no mail sent)

- Required name/email/message/privacy acknowledgment and invalid-email rejection.
- Question/correction mode does not require fees, rights or project terms.
- Submission failures preserve entered fields; repeated clicks do not send duplicate requests.
- Native form fallback and keyboard navigation remain usable.
