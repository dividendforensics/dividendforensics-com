# PR15 검수 후속 조치 — 2026-10-19

## 변경 범위

PR15의 계산값과 사이트 구조는 유지한다. 원문 열 선택, 상태 안내, 배포 검증 증거의 세 항목을 보완한다. 외부 검수의 통과 수치를 이번 실행 결과로 합산하지 않는다.

### Apple 자본변동표 근거

- SEC 원본 10-K: https://www.sec.gov/Archives/edgar/data/320193/000032019324000123/aapl-20240928.htm
- SEC XBRL workbook: https://www.sec.gov/Archives/edgar/data/320193/000032019324000123/Financial_Report.xlsx
- 원본 HTML의 인쇄 쪽수 표기로 자본변동표 32쪽, 현금흐름표 33쪽, Note 4의 현금 에스크로 각주 37쪽, Note 10의 주식 수 표 44쪽을 확인했다. PDF 파일의 물리적 페이지 번호를 뜻하지 않는다.
- 원본 32쪽 FY2024 `Retained earnings/(Accumulated deficit)` 구간의 `Common stock repurchased`는 −95,846 USD million이다. 해당 구간은 −214 + 93,736 − 15,218 − 1,612 − 95,846 = −19,154로 닫힌다.
- 원본 workbook을 내려받아 openpyxl로 열었다. `CONSOLIDATED STATEMENTS OF SHAR` 시트의 29행에서 Total(B29)은 −95,000, Retained earnings/(Accumulated deficit)(D29)은 −95,846이었다. 846 차이의 원인을 추측하거나 발행사 오류라고 단정하지 않는다.
- 실습의 레이블·위치·측정 기준을 구체화하고, 원본 구간의 잔액 검산과 workbook의 다른 열을 구분하는 설명을 추가했다. 95,846과 현금 94,949의 차이 897은 유지한다. 차이만으로 세금·정산시점 원인을 만들지 않는다.
- 실습의 실제 수정일만 2026-10-19로 변경한다. 최초 발행일과 기존 36개 입력값의 2026-10-18 원문 확인일은 보존한다.

### 현금흐름 작업 화면의 음성 상태 안내

선택 입력이 없을 때 `null`을 실제 불일치와 같은 문구로 읽던 것을 수정했다. 입력 누락은 `not checked`, 차이 0은 `matches`, 0이 아닌 차이는 `unreconciled`와 차이값으로 구분한다. 화면 결과·CSV·산식은 변경하지 않는다. JS와 페이지 참조 버전은 `operating-1.0.1`이다.

실제 브라우저 검사에 보고 OCF 누락, 선택 현금 항목 5개 전체 생략, 실제 불일치, 수정 후 회복을 포함했다. ARIA 속성과 live-region 텍스트를 검사한 것으로, 실물 스크린리더 음성 청취 검증은 아니다.

### 배포와 검증 증거

- `main.yml`은 커밋된 결과물을 읽기 전용으로 검증한다. 자동 생성 커밋·push와 별도 Pages 재빌드 요청을 함께 제거한다. PR에 생성 결과를 포함하고 `build_site.py --check`를 통과시킨 뒤 병합하는 흐름이다.
- 별도 POST만 제거하고 `GITHUB_TOKEN` push를 남기면 Pages가 갱신되지 않을 수 있다. [GitHub 토큰 문서](https://docs.github.com/en/actions/concepts/security/github_token)의 동작을 반영했다.
- 공개 검증은 성공한 동일 저장소 main의 Pages 실행을 대상으로 해당 SHA를 고정해 수행하도록 설정한다. 수동 실행도 main의 실행 당시 SHA를 고정한다. 토큰 권한은 contents read이며 PR 코드나 PR artifact를 실행하지 않는다.
- JSON 증거에는 소스 커밋·tree, UTC 시각, 검증 실행과 Pages 실행 연결을 남긴다. 시작·진행 중 증거는 실패/미완료 상태이고, 일반 공개 URL 전체가 일치해야 통과한다. 캐시 우회는 진단만 한다. 실패·시간초과 때도 남은 증거를 Actions artifact로 올리도록 한다.
- PR15 완료 문서의 제품 Pages와 후속 문서 전용 Pages를 구분했다. 예전 로컬 170/170 파일에는 실행 연결 메타데이터가 없었다는 한계도 명시했다.
- 자동 트리거와 공개 artifact가 실제로 생성됐다는 판정은 병합 뒤 새 Pages 실행에서 확인해야 한다. 설정 파일 존재만으로 배포 완료를 주장하지 않는다.

## 이번 로컬 검증

Python 161개, Node 95개 통과. 활성 HTML 145개 구조 검사 및 사이트맵 133개 SEO 검사 통과(오류 0, 기존 길이 권고 2). 수정된 생성 결과로 새 경로 5페이지 × 5폭 = 25 렌더와 동작 10항목을 직접 실행했다. JS 오류와 실제 폼 전송은 0이었다. 저장소 전체 브라우저 CI 및 병합·공개 검증은 별도 실행 기록으로 확인한다.

## 저장소 설정의 미완료 항목

원격 조회에서 main은 `protected: false`, rulesets는 빈 목록이었다. GitHub 연결 도구에 보호 설정을 바꾸는 기능이 없으며, 내장 브라우저의 설정 화면은 로그아웃 상태여서 접근할 수 없었다. 보호 설정을 변경했다고 주장하지 않는다.

운영자가 적용할 값: main에 PR 필수, 필수 검사 `review`(GitHub Actions, app ID 15368), 최신 base 요구. 1인 운영이라 필수 사람 승인 수는 0으로 둘 수 있다. `build`와 배포 후 `verify`는 PR에서 실행되지 않으므로 PR 필수 검사로 지정하지 않는다. 보호가 없으면 직접 main push가 검사보다 먼저 Pages 배포를 시작할 수 있다. 이번 변경은 PR의 `review` 통과를 직접 확인한 뒤 병합한다.

## 범위의 한계

이번 작업은 AdSense 승인·검색 색인·실제 메일 수신·실폰·원어민 감수의 검증이 아니다. 광고 코드나 계정 설정을 활성화하지 않으며 기존 AdSense 확인 정보는 유지한다. 이전 원문 입력 전수 검수와 이번 열·쪽수 보완 검수를 구분한다.
